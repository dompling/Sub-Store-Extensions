# 规则集配置 Chrome 桌面端修复计划

## 已复现问题

- 双列桌面布局中，`nut-swipe` 的刷新、预览和归档操作区在未展开时仍显示在卡片右侧。
- 规则库管理页只有内置规则库，缺少添加、编辑和删除第三方 GitHub 规则库的完整入口。
- 已有规则集按要求默认折叠后，桌面编辑页只剩三条缺少摘要的折叠栏；新建页又把移动表单直接拉宽，内容层级和密度都不符合现有插件。

## 行为保护

- 移动端继续支持滑动操作；桌面端改为卡片内部展开操作，避免动作溢出到网格列外。
- 已有规则集编辑时继续默认折叠，新建项目继续默认展开基本信息和来源。
- 已添加到项目的规则来源仍保存为普通 URL；删除规则库不会删除或修改项目来源。
- 内置规则库保持只读，只有用户添加的规则库可以编辑或删除。
- 不新增依赖，不跨插件读取源码、存储或私有路由。

## 实施顺序

1. 先增加桌面列表、编辑摘要、规则库 CRUD 和存储迁移回归测试。
2. 将 Rule Studio 存储升级到 schema 3，保存自定义 GitHub 规则库。
3. 增加规则库创建、更新、删除 API，并复用现有 GitHub 目录索引、缓存和限流回退。
4. 规则库页通过宿主左上角加号打开系统风格弹层，支持 GitHub 目录 URL、名称和格式。
5. 桌面列表使用卡片内展开操作，移动端保留 swipe。
6. 编辑页删除占空间的常驻概览，改成紧凑折叠卡、折叠摘要、来源摘要和系统风格来源弹层；已有项目仍默认折叠。
7. 预览详情页改成项目摘要、格式选择、四项统计、输出和分组诊断的清晰层级。
8. 构建、打包、重新安装到本机 3000 后端，并在用户 Chrome 中按桌面路径回归。

## 完成标准

- Chrome 桌面端列表未展开时不存在悬空操作按钮，单列和双列均正常。
- 可以添加、编辑、启停、刷新和删除自定义 GitHub 规则库。
- 规则集编辑页即使全部折叠，仍能看懂项目名称、启用来源数量和当前规范化选项；展开后不出现横向拉伸或大面积无意义留白。
- TypeScript、Rule Studio 测试、repository verify、`git diff --check` 全部通过。
- Chrome 桌面截图视觉评分达到 90 分以上。
